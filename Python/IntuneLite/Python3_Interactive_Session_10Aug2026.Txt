Note: 

How to Make Your JWT Tokens Stronger in create_access_token
To make tokens enterprise-grade and resilient against security risks (such as token replay attacks, cross-site forgery, or token hijacking), 
you can add standard cryptographic claims defined in RFC 7519 (JWT Standard):

--------------
import uuid
from datetime import datetime, timedelta, timezone
from typing import Any, Optional
import jwt
from app.core.config import settings

def create_access_token(
    subject: str | int,
    expires_delta: Optional[timedelta] = None,
    extra_claims: Optional[dict[str, Any]] = None,
) -> str:
    now = datetime.now(timezone.utc)
    
    if expires_delta:
        expire = now + expires_delta
    else:
        expire = now + timedelta(minutes=settings.ACCESS_TOKEN_EXPIRE_MINUTES)

    # Base payload structure with enterprise security claims
    to_encode = {
        # 1. Existing RFC Claims
        "sub": str(subject),                         # Subject (Who the token belongs to)
        "exp": expire,                               # Expiration time
        
        # 2. Key Security Additions
        "iat": now,                                  # Issued At (Exact time token was generated)
        "nbf": now,                                  # Not Before (Token is invalid prior to this timestamp)
        "jti": str(uuid.uuid4()),                    # JWT ID (Unique nonce for token revocation / blacklist tracking)
        "iss": "intunelite-auth-service",            # Issuer (Identifies who generated the token)
        "aud": "intunelite-api",                     # Audience (Identifies the target recipient API)
    }

    # Merges extra claims (e.g., role, department)
    if extra_claims:
        to_encode.update(extra_claims)

    encoded_jwt = jwt.encode(
        to_encode, settings.SECRET_KEY, algorithm=settings.ALGORITHM
    )
    return encoded_jwt

    When working on enterprise applications with dozens of files, a Python stack trace can look terrifying at first glance. However, there is a simple 3-step technique to debug them instantly:

    Step 1: Read the Very Last Line First (The "Root Cause")
    Always scroll to the bottom line of the traceback. Python places the actual error message at the very end.

    In your log: ImportError: email-validator is not installed...

    This immediately tells you what went wrong without needing to read all 40 lines above it.

    Step 2: Scan Upwards for "Your Code" (Ignore Library Files)
    The middle of a stack trace is filled with framework code (like uvicorn, pydantic, asyncio). Filter out anything referencing site-packages or /usr/lib/ and look for paths pointing to your project directory (/Intune_Lite/...).

    Scanning your log from top to bottom, we find the exact file propagation path:

    main.py, line 32: from app.api.v1.admin import router as admin_router

    admin.py, line 14: from app.schemas.user import UserResponse

    user.py, line 39: class UserBase(BaseModel): (where email: EmailStr triggered the import check)

    Step 3: Connect the Trail
    By reading the trail: main.py imported admin.py, which imported user.py, which tried to evaluate EmailStr, which failed because email-validator was missing

from app.db.session import engine, SessionLocal
from app.core.security import create_access_token, decode_access_token

from app.schemas.user import UserResponse
from sqlalchemy import select

db = SessionLocal()

# 3. Simulate Endpoint Token Verification -> Decode JWT
payload = decode_access_token(access_token)
extracted_username = payload.get("sub")
print(f"\n3. Token Decoded Successfully! Extracted Subject ('sub'): '{extracted_username}'")

# 4. Simulate Dependency DB Fetching
authenticated_user = db.execute(
    select(User).where(User.username == extracted_username)
).scalar_one_or_none()

print(f"\n4. Authenticated User Entity Retrieved:")
print(f"   Name: {authenticated_user.full_name} | Role: {authenticated_user.role}")

user_response = UserResponse.model_validate(authenticated_user)
print(f"\n5. Serialized Outgoing JSON Response (Notice hashed_password is stripped!):")
